## 实现

- `frontend/` 收入 558 个来源文件，包括 477 个图片、模型、字体与音频资源。来源是 MJAI 提交 `c994064ecd44b1b005c6f65e47309ec75bbc4d6f` 上的工作区快照；逐文件源哈希、导入后哈希和授权记录保存在 `hand-parity-manifest.json`。
- 8 个来源文件仅作入口、连接、身份与本地偏好适配。其余渲染、UI、动画、声音、CSS 和资源保持原始内容。新增独立启动入口在加载牌桌前兑换邀请 Cookie，删除地址栏票据，刷新与 WebSocket 重连复用同一座位；不使用 MJAI 登录、账号或数据库。
- 同仓库构建产物通过 Worker ASSETS 提供。保留原始 1280×720 比例、contain 缩放和居中。原教学局部案例也可使用独立前端，不需要访问源 MJAI。
- 服务端为真人原操作匹配合法动作，校验决策时限、座位和重复请求；初次连接发送完整视图，后续发送变化，保留原牌桌动画触发方式。
- 修正状态恢复对象共享引用导致变化被漏发的问题。向原 HUD 提供服务端超时配置；其他玩家已选牌只显示完成状态，不传其选牌标识。
- Harness 独立服务配置默认使用同源 `/hand/`；桌主参与时直接打开本人的真人席，全 AI 时打开旁观席。官方 Harness 核心未修改。

## 验证

- 前端 TypeScript、全部来源文件哈希、服务 TypeScript、14 个规则来源校验通过。
- 插件 101 项测试通过；服务 16 项测试覆盖 0–4 真人组合的整局血战、保存恢复、超时、信息隔离、真人动作、Cookie 身份交换、跨来源拒绝、增量同步和重连。服务测试运行在本地真实 workerd 与 SQLite Durable Objects 中。
- 三种尺寸固定案例与原 `/hand/` 对照：1280×720、1920×1080、640×800，牌面、位置、桌布和 HUD 一致。保留原有动态萤火虫，因此截图不是逐像素完全相同；平均通道差值均小于 0.05/255。窄容器保持 640×360 牌桌居中，上下用原背景补齐。
- 浏览器验证真人换三张、定缺、出牌、明杠、刷新与断线重连；原出牌音效与报牌音频有实际播放调用并正常加载；成功清理票据，脚本读不到会话 Cookie，刷新后资源请求无 4xx。
- 部署包试构建通过，没有登录 Cloudflare、创建远端资源或调用付费模型。用于界面验收的其他座位只提交预设合法动作，不代表真实模型表现。后半局由测试脚本通过原客户端动作通道继续到 `done`，并打开原结算界面；测试脚本首次在视图更新前读取响应编号，被服务按非法动作拒绝，调整为等视图更新后再操作，未修改生产规则。
