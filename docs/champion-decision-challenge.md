## 1. 产品判断与建议

这个想法合理，适合做成“冠军案例 → 自己判断 → 关键一步讲解 → 接手实战 → 结果与决策复盘”的学习产品。价值在于把观看比赛变成可操作、可解释、可重复练习的决策训练。

建议首版定位为**冠军关键决策讲解与同局面接手挑战**。可以比较用户与冠军在这一刻的选择，但不能凭一次续打赚得更多，宣称用户的整体水平超过冠军。

首版必须成立的四个条件：

1. 赛事来源可核实，素材有适用的使用依据，牌谱完整程度能够核验。
2. 决策评价只使用冠军当时可知的信息，不能偷看后来摸到的牌或其他人的暗手。
3. 接手后创建独立分支，对手优先沿用适用的原牌谱动作，仅在新局面需要时补选，原比赛牌谱保持不变。
4. 分开报告实际输赢、这一步的预期收益和长期表现，明确模拟假设与不确定性。

首例已定位为2026年9月2日总决赛录像第1个分P中的「第5局｜第1副」，原视频00:00–05:25。当前记录84条行牌动作，已通过程序一致性检查，逐项视频核对未完成；主讲选手为冠军队成员周猩猩。未摸19张的真实顺序未知，完整赛事规则仍待补证。

## 2. 范围与术语

| 名称 | 本文含义 |
| --- | --- |
| 赛事／场次 | 可能包含多副牌，有独立积分、排名和夺冠规则 |
| 一副牌 | 从发牌、换三张／定缺等适用阶段，到血战规则规定的最终结算 |
| 冠军 | 经赛事正式结果确认的选手，不等于某一副牌的最大赢家 |
| 关键一步 | 冠军在某个明确时点拥有多个合法选择、值得分析的决策 |
| 原比赛回放 | 只读展示已发生的真实动作，不允许用户改变历史 |
| 接手分支 | 从决策发生前的状态另开一局，用户控制冠军原座位；其他座位默认沿用适用的牌谱动作，必要时由 AI 补选 |
| 同局面随机练习 | 保持该时点已知信息，按明确方法生成未知手牌与牌墙；不声称是原比赛隐藏状态 |

首版只做血战到底，先支持**普通轮到自己弃牌的决策点**。抢杠、多家响应、换三张、定缺等其他类型，待各自的状态边界、评价方法和测试补齐后再开放。赛事规则与当前规则不一致时，必须先明确差异并补齐相应规则版本，不能直接套用当前血战配置。

这里的“续打”指把这一副牌从关键一步打到结束。继续模拟赛事的下一副牌、整场排名或夺冠概率属于后续扩展，需要对应的完整赛制和场次资料。

## 3. 用户体验

### 3.0 内容制作与交付顺序

整体流程是：**整理一副完整历史牌谱 → 在麻将实验室完整回放 → 扫描并精选关键一步 → 在麻将实验室讲解、录制 → 交付成片、标题、简介和封面等 → 用户查看并手动发布B站视频 → 发布同一步的接手挑战 → 补齐视频与挑战互链及结果评价**。

这条制作链路与下述学习流程不同。B站观众先看讲解再来玩，属于已看讲解的练习；平台内部仍可为未看答案的访问者提供先作答、后揭晓的路径，但不能凭首次访问就认证盲测。

我们负责真实录制、完整投稿素材包和挑战功能；用户负责查看后手动发布视频，以及更新B站简介或评论中的挑战入口。素材制作交付、用户发布、公开挑战与互链分别验收；挑战开发与内部测试无需等待用户发布。详细产物、责任划分和状态以[完整流程文档](champion-content-workflow.md)为准，不将本地素材交付标为已投稿。

### 3.1 一次完整学习流程

1. **了解背景**：展示赛事、场次、选手、规则、该步所在位置、来源和数据完整度。冠军身份可显示，后续动作及结果默认隐藏。
2. **先自己选择**：用现有真实牌桌展示冠军当时能看到的局面，用户选择合法弃牌，可简述理由。提交前不透露冠军答案、推荐答案和后续摸牌。
3. **看讲解**：展示冠军实际选择，以及两到三个有代表性的备选；解释牌形、进攻速度、收益、风险和局面条件。
4. **接手打完**：用户选择从该步继续，其他有效座位优先沿用适用的牌谱动作，仅在无法沿用或新局面需要调整时由 AI 补选。页面标注“牌谱优先接手”，复盘可查看哪些动作被保留、哪些被调整及原因。
5. **看复盘**：并列展示本次净输赢、原比赛同期实际净输赢、该步模拟评价、值得改进的后续决策及相应依据。
6. **检验是否学会**：进入没见过隐藏牌的变式或其他同类案例，观察首次作答和多局表现。

流程允许“先完整挑战、后看讲解”。已看答案、使用提示、查看原比赛后续或重复固定牌墙的记录标为练习；不与未揭晓答案的首次挑战混排。公开比赛的视频本身可能已被用户看过，因此首次访问也不能保证绝对盲测，正式能力评价需要另外准备未公开的保留题集。

### 3.2 页面与讲解内容

沿用真实 `/hand/` 牌桌、原素材和 1280×720 等比布局。新增案例导航、候选动作卡、讲解和成绩放在 Harness 外层面板；具体交互设计不得擅自重画或替换牌桌。

一张讲解卡应包含：

- **此时知道什么**：自己的手牌、换三张时自己换出和收到的牌、此前自己可见的行动，以及公开弃牌与副露、定缺、已胡状态、余牌数、当前计分情况。
- **能出什么**：由规则服务提供全部合法动作；策略等价的同种牌可以合并说明。
- **冠军怎么选**：准确对应原记录，并给出来源步骤或时间点。
- **候选比较**：候选的进张／听牌变化、可能收益、放铳与终局罚分风险。涉及概率必须来自可追溯的评估结果。
- **推荐及条件**：例如“在当前对手模型下，这个选择的估计平均收益更高”；证据不足时显示“暂时无法可靠区分”。
- **可以迁移的原则**：解释遇到类似局面时该看哪些信息，而不只是记住某张牌。

区分“冠军实际做了什么”“我们对其理由的分析”和“冠军本人公开说明的理由”。没有可靠来源时，不把分析写成冠军的真实心理活动。

讲解可以在提交后提供全信息复盘，但全信息视角必须单独标识，不能回流成为这一步的盲测评分依据。原比赛后来摸到好牌，只能作为历史叙述，不能证明当时选择必然最佳。

## 4. 赛事牌谱与数据要求

### 4.1 三种数据能力

| 级别 | 实际掌握的数据 | 可开放的功能 | 必须保留的限制 |
| --- | --- | --- | --- |
| A：可完整重建 | 规则、四家起手牌、全副动作、结算均可核验；关键点全部隐藏状态、完整余墙顺序与既有结算关系可恢复 | 完整回放、原隐藏状态接手、随机变式、决策分析 | 严格原牌墙与个人摸牌优先为不同模式，均不能冒充原选手真实的另一种未来 |
| B：历史牌谱完整、余墙不全 | 四家起手牌、全副摸打和响应、暗手演变及结算可核验，但原局结束时未摸出的牌墙顺序不全 | 完整历史回放；合条件时提供原摸牌优先训练、明确补全余墙的接手与分析 | 补全部分必须标为“模拟余墙”，不能叫“完整原牌墙续打” |
| C：局部片段 | 只有局部视频、截图或若干手牌快照 | 已验证局面的教学展示；信息充分时做局部条件分析 | 不能宣称拥有完整牌谱、找到全副最关键一步或准确还原后续 |

能力由字段与校验结果决定，不能由文件名或人工填入的“完整”标签决定。原比赛的全部摸牌记录，仍可能没有包含原局结束时剩余的牌墙；分支可能比原局持续更久，这部分缺失也会阻止完整原牌墙续打。

新确认的首例制作链路必须先取得完整历史牌谱。C级素材只能用于补证或内部试验，不能以片段教学替代用户要求的完整牌局；A、B两级的区别在余墙及续打方式，不能把四家起手牌和历史动作未确定的情况归入B级。

如果只掌握完整可信的关键点状态，而不是整副动作，可以提供该点续打；但仍不能宣称已经扫描整副比赛找出了最关键的一步。**全局选题完整度与单点续打完整度分别登记。**

### 4.2 导入、核对与发布流程

优先取得主办方、赛事平台或有权提供者的结构化记录。只有视频时，识别工具只负责生成草稿，人工核对动作顺序、座位、牌张、漏镜头和结算；无法辨认的内容保留未知，不用模型猜测填成历史事实。

案例至少登记：赛事与场次标识、冠军身份依据、原始来源定位、权利使用记录、规则文本及版本、座位和起始状态、事件序列、积分单位、最终结算、已知／未知字段、人工复核记录。可续打案例另存私有的完整检查点、牌墙位置、历史结算义务和完整性校验值。各座位在此前实际观察到的私有信息也需恢复，例如换三张的去向与内容，不能只保存当前手牌而丢掉选手当时可以记住的信息。

在服务端按对应规则重放全副动作，核验牌张数量、合法动作、摸牌与响应顺序、各次分数转移及最终结果。无法对齐时先排查缺失记录与规则差异，不能偷偷改原牌谱让它适配程序。

发布流程为：**来源与使用范围登记 → 数据核验 → 规则重放 → 关键点筛选 → 分析与人工复核 → 发布教学内容**。任一案例可独立暂停或撤回，不影响其他牌局。

公开回放、教学内容与私有完整状态采用不同访问权限。赛事隐藏状态、凭证及未获准分发的原始素材不进入公共 Git 仓库或默认安装包；源代码开源不自动使赛事数据获得再分发授权。

## 5. 怎样选择“关键一步”和判断最佳弃牌

### 5.1 先明确评价目标

首版默认目标是：**在当时可知信息下，最大化从该步开始到本副最终结算的预期净得分**。同时展示风险与收益波动，不强行将它们混成一个含义不明的总分。

“本副多赢分”不一定等于“整场更容易夺冠”。如果要分析冠军在积分领先或落后时的赛场取舍，必须提供该时点整场积分、剩余副数、排名和晋级规则，并预先切换评价目标。没有这些数据时，只做本副收益分析，不判定选手的赛事策略错误。

麻将含有随机性和不完全信息，不能只按最终胜负倒推决策好坏；麻将研究也将这些视为核心困难。Suphx 研究可支持这个一般判断，但其规则与评估结果不能直接当作本项目血战 AI 的实力证明。[微软 Suphx 研究](https://www.microsoft.com/en-us/research/project/suphx-mastering-mahjong-with-deep-reinforcement-learning)

### 5.2 筛选流程

1. 对全副中符合首版边界的决策点，生成当时视角与全部合法弃牌。
2. 使用只依赖该时点可知信息的评估器，估计各选择的收益、风险与不确定性。
3. 综合候选之间差异、冠军选择与候选的差异、讲解价值和数据可信度，给出少量候选步骤。
4. 由懂该赛事规则的复核者确认教学主题、事实和解释，再选出首个发布案例。

首版采用“辅助筛选＋人工选题”，不承诺自动找出数学意义上唯一的全局关键一步。若多个步骤均有价值，显示“本局精选关键一步”。只有一个合法动作、差异不显著或数据不足时，不制造“冠军神之一手”。

冠军的选择可能与模型推荐相同，也可能不同；产品应如实解释差异，不能为了选题预设冠军永远正确。模型的结论同样需要复核，不能因为与冠军不同就宣称发现了冠军失误。

### 5.3 推荐结论的强度

- 规则引擎负责“是否合法、怎样结算”；策略评估器负责“在这些假设下，哪个选择更有利”；讲解模型负责把可验证的结果说清楚。
- 对手行为与未知牌的分布都属于建模假设。至少用不同合理对手风格检查推荐是否稳定；排序改变时说明推荐依赖的条件。
- 数值相近或样本不足时，允许多个合理选择，不强行选一个“唯一最佳”。
- “95% 区间”只描述评估方案中的抽样不确定性，不能涵盖对手模型错误、采样偏差或现实比赛中的全部变化。
- 上线文案使用“模型估计推荐”“在本评估条件下更优”，不承诺真实比赛必胜或绝对最优。

## 6. 改变出牌以后，牌局怎样继续

### 6.1 默认保留原比赛，只做必要调整

在冠军**尚未作出该步动作**时冻结状态并创建新牌局。原比赛从始至终保留为只读参考；用户的动作、后续牌局和结算写入独立记录，并关联来源案例、步骤与规则版本。

用户本人从该点继续操作，直到本副结束或明确选择托管。其他三家的默认控制方式为**牌谱优先、必要时补选**，每个有效决策点分别检查：

| 当前情况 | 动作处理 |
| --- | --- |
| 仍与原记录的对应局面一致 | 严格沿用原动作，不因 AI 自认为有更优选择就修改历史打法 |
| 局面已有变化，但原动作合法，且变化没有使它明显不适用 | 继续沿用原动作，尽量保留原比赛 |
| 原动作不合法、没有对应决策点，或新变化使其明显不适用 | 仅为当前决策补选；之后每一步仍重新检查能否沿用牌谱 |

在所需原状态和原牌序已知、用户始终按冠军原动作操作时，所选模式必须能够重现原比赛的其他动作及结算。时间戳可以不同，但不能无故更改牌张、响应与分数。

“明显不适用”不能等于“AI 找到一个稍好的选择”。需要有可记录的原因，例如这张牌已不在暗手、定缺要求不允许该弃牌、原碰牌事件已不存在，或新增摸牌／副露／公开信息让照谱产生明显的额外决策损失。没有新变化时，不顺便纠正原选手本来就作过的不完美选择。

新出现的胡牌、碰杠机会也必须先进入规则允许的响应流程，再由该座位策略判断，不能因为原牌谱没有记录就自动忽略；也不能一律规定“有碰就碰”或“有杠就杠”。

例如，在两张牌都合法的假设局面中，冠军弃九万，用户改弃六筒。新的六筒可能被碰、杠、胡，也可能无人响应。没有受到实质影响的对手动作继续保留；发生变化的动作局部补选。不能因为用户改了一张牌就把后面全部重写，也不能要求每一张后续出牌都完全不变。

“严格原牌墙”只表示保留相同的物理牌墙及其取牌规则。碰杠、补牌和轮次发生变化后，同一张牌可能被另一座位摸到。用户希望每个人尽量摸到原来的牌，因此默认采用第6.6节的“个人摸牌优先”改编训练；界面和报告必须区分两种条件。

### 6.2 原牌谱不能直接用时，怎样选择弃牌

补选站在**正在出牌的那位对手**的立场，不以帮助挑战者获胜为目标，也不故意惩罚用户偏离牌谱。补选程序依次完成：

1. **过滤不合法动作**：只在当前规则服务发放的动作集合内选择，遵守定缺、响应阶段和过手等限制。
2. **比较真实选择**：依据该座位当前手牌及其可知历史，估计进张、听牌变化、可能收益、放铳风险和适用的终局损失。不能固定用“总打孤张”或“总打新摸牌”替代局面判断。
3. **形成可接受候选集**：排除有明确证据表明明显更差的动作；收益差阈值、估计不确定性的处理方式随策略版本固定。策略判断不确定且原动作仍适用时，默认保留原动作并记录不确定性。
4. **在接近的选择中尽量保留原打法**：原动作仍在可接受集合时优先采用；原动作不适用时，在收益接近的候选中优先保留原副露与手牌组合、进攻方向和风险取舍，避免不必要地改变后续。此处是可观察牌形的延续，不声称知道原选手的内心意图。
5. **记录并继续**：记录原拟动作、实际动作、替换原因和策略版本；下一步再次尝试匹配适用的原记录，而非永久切为自由 AI。

对合法原动作的替换，必须先通过“由新变化触发”的检查。可离线比较原局面和新局面中该动作相对其他候选的劣势是否明显增加；不能只因它在原局面里也不是评估器的最优选择就替换。具体阈值需用案例校准，首版不凭空承诺一个通用数值或固定保留率。

这借鉴了“在可接受的动作中尽量贴近原建议、只作必要干预”的控制思路；相关研究用于人机协作控制，并非已经验证本项目的血战算法。本方案仍需独立实现和验证。[伯克利：Shared Autonomy via Deep Reinforcement Learning](https://bair.berkeley.edu/blog/2018/04/18/shared-autonomy/)

一个假设例子：原选手摸到九万后立即弃九万，新分支却摸到八条。不能机械地为了牌名一致，就从原有组合里拆一张九万。先判断新摸的八条是否改善牌形、哪些弃牌合法以及收益风险；如果八条无用可以弃八条，如果有用则重新选其他合理弃牌。没有完整手牌时，不能预先断言这两张中的哪一张必然最好。

### 6.3 对齐步骤、补选后恢复与偏离记录

牌谱动作不是一个只需不断取“下一条”的全局队列。每个原动作都要绑定座位、动作阶段、触发弃牌或摸牌、暗手／副露、公开历史和有关的规则结算状态。

- 原来因九万产生的碰牌，不能套在新出现的六筒上；新产生的碰杠响应没有历史对应动作时，单独补选。
- 改变轮次后，不得把原记录中别人的下一手强行分配给当前座位，也不把原谱后几手提前搬来凑一个合法弃牌或响应动作。第6.6节的摸牌序列顺延另行处理，不能用它改写动作对齐规则。
- 补选后只有在对应决策条件再次匹配时，才能沿用匹配的原动作；仅仅手牌长得相似，不足以宣称回到原历史。
- 无法匹配时，可以延续可解释的牌形偏好并继续合理补选，不能为提高保留率重置暗手、牌墙或积分。
- 原谱结束而分支仍未结束时，按同样的补选策略打到规则规定的终局；原余墙不全时按数据完整度限制处理。

复盘显示“沿用原谱／因新局面补选”以及具体理由。统计保留次数、替换次数、无对应历史的新增动作和首次偏离点；如果展示比例，必须给出统计分母，跳过或新增的动作不能被用来虚增保留率。

### 6.4 隐藏信息与 AI

服务端可以持有完整状态以执法和推进牌局，但每个 AI 只接收自己的暗手与公开信息；讲解会话和裁判状态不能借给 AI 偷看。用户也只能看到自己座位允许的信息。

原比赛牌谱只能告诉我们选手在实际历史中做了什么，不能告诉我们他面对另一种局面会怎么做。沿用的动作标明来自原记录，补选的动作标明来自模拟，不能把整个分支称为原选手的真实策略或“冠军分身”。

默认的牌谱优先控制器只向补选策略提供当前座位视角及适用的单步参考，不把原比赛后续完整暗手、摸牌与终局答案喂给它。但是，参考动作本身来自已经发生的历史，可能间接带有该历史路径的信息，因此这种模式属于**有牌谱条件的复盘练习**，不能作为无剧透的通用能力评估器。第 7.3 节的独立决策评估必须另用不读取本案例未来动作的策略。

血战在首家胡牌后通常还会继续，应按案例锁定的规则处理已胡玩家、后续胡牌及最终结算，不得直接套用一人胡牌即结束的模式。

### 6.5 必须继承此前的结算关系

原始手牌、弃牌和牌墙以外，还要继承定缺、已胡状态、轮次、杠的类型与支付关系、累计积分，以及规则要求的过手限制、有效响应状态等。首版只在普通弃牌边界分支，不能把原历史中这一步之后才提交的响应偷偷带入新局。

**历史杠分尤其不能清空。** 例如甲在接手前因杠向乙支付 200 分；若适用规则要求乙在流局未听时退税，那么接手后仍可能发生乙向甲退回 200 分。这个未来退款属于接手期间的收益，依赖接手前的付款记录。

现有独立练习会重新起算积分、清空流水及部分累计值。冠军接手需要新增保留历史结算上下文的分支方式，不能直接沿用这一重置逻辑。

默认 4,800 分继续用于普通新开桌。赛事案例保留真实积分、单位与底分；如教学界面另显示“练习余额 4,800”，必须标明换算或偏移，不能覆盖原结算状态或改变赛事策略。首版建议直接显示赛事当前积分，同时醒目显示“接手后净得分”。

### 6.6 四家个人摸牌尽量沿用原谱

用户已明确希望：接手者可以自由选择合法弃牌，四家摸牌都尽量与原局一致；原定牌已不可用时，顺延到该玩家原记录中的后续摸牌。默认训练按此设计，名称为“原摸牌优先”，不能把它描述为严格物理牌墙原样运行。

服务端为各座位保存带顺序和来源事件的摸牌序列游标，并为可恢复的牌张分配内部实体标识。候选牌只有仍在可用牌池、且符合当前事件条件时才能取出；不能从任何玩家暗手、弃牌、副露或已胡牌中取回牌，也不能因同名牌有四张就重复使用同一个实体。原记录无法区分同名实体时，采用固定的等价实体匹配规则并记录，不伪称知道原录像未展示的物理编号。

| 情况 | 默认处理 |
| --- | --- |
| 到该座位的正常摸牌事件，原对应牌可用 | 优先给原对应牌，推进该座位游标 |
| 原对应牌已用掉或不符合当前事件条件 | 跳过并记录原因，沿该座位的原摸牌序列寻找下一张可用牌；不能改抓别人当前持有的牌 |
| 碰、杠、胡改变轮次或出现额外补牌 | 先由规则服务确定谁是否应摸牌、正常摸牌或补牌；再按固定序列匹配和补牌规则取牌，不为了保留个人牌序取消合法响应 |
| 该座位原摸牌序列耗尽或无可用候选 | 按预先锁定的剩余牌池顺序补足；已知余墙优先复用，未知部分采用标明来源的固定模拟补全 |
| 无合法剩余牌可摸或达到赛事终局条件 | 按规则结束并结算，不为满足原谱补造牌 |

牌池、各座位游标、补牌处理、跳过事件和随机种子随分支保存；额外补牌后的游标推进及同名牌匹配在实现版本中锁定，刷新或重复请求不得二次消耗。不同分支中的牌张总数始终守恒。

个人摸牌优先使用原局未来摸牌作为条件，是用户指定的训练机制。它只用于服务端推进，不能向用户或补选AI提前展示下一张牌；独立单步能力评估仍使用第7.3节的无未来脚本策略和真实规则取牌。成绩标明摸牌模式，两个模式及模拟余墙的成绩不得混排行。

## 7. 怎样评价“是否打得比冠军好”

### 7.1 三个问题分别回答

| 用户想知道的事 | 评价方法 | 可以说什么 | 不能据此说什么 |
| --- | --- | --- | --- |
| 这一次续打结果怎么样 | 接手到结束的实际净得分，另列原比赛相同起点后的实际净得分 | “本次续打比原比赛同期多得分” | “你的水平已经超过冠军” |
| 这一张牌是否选得更有利 | 在同一批合理隐藏局面、同一套后续策略下，成对模拟用户动作与冠军原动作 | “本评估条件下，该选择估计平均收益更高／证据不足” | “冠军在所有真实对局中都会输给你” |
| 用户后半局是否打得更好、是否学会了 | 多个未见案例的完整挑战，结合各自实际遇到的局面评价后续决策 | “在这组题目和基准下表现更稳定／优于参考策略” | “分支里每一步都能逐手比较冠军真实动作” |

分支发生以后，冠军没有在用户遇到的新局面里作过选择，因而后续只能与明确的参考策略比较。牌谱中原冠军后半局的收益可以作为历史参照，不能把两种对手与两条路径混成严格的能力实验。

### 7.2 本次结果的计算

```text
接手后净得分 = 本副最终积分 − 接手瞬间积分
历史同期净得分 = 原比赛最终积分 − 原比赛该步骤前积分
```

同一起点的本次得分差可以直接展示，并标为“牌谱优先条件下的接手结果”，同时展示哪些对手动作被补选及原因。它回答“尽量保留这副比赛时，你这次打出了什么结果”，不能单独证明策略普遍更好。最终结算包含适用的杠分、胡牌得分、查花猪、查大叫和退税，不只数胡牌次数。

血战允许多家胡牌，所以“胡牌比例”“净得分为正的比例”“本副最高净得分比例”是不同指标，应分别命名，不统一叫含义不明的“胜率”。

### 7.3 单步决策的公平模拟

定义当时允许使用的信息为 `I`，用户与冠军的实际选择为 `a_user`、`a_champion`。

1. 根据 `I` 生成一批合法隐藏局面 `W_i`，包含未知手牌和余下牌墙；采样不能使用原比赛这一步之后的动作、暗手揭晓或结局。`I` 包括该座位此前的私有观察和公开历史，例如换出去的牌及去向。采样须符合牌张数量、已发生动作和所有已知条件；仅均匀打乱剩余牌不等于已经正确建模对手的暗手分布。
2. 在每个 `W_i` 中分别执行两个候选动作，其余条件配对保持一致。
3. 两个分支中，三个对手使用相同版本、只读取各自可知信息的独立响应策略，不能读取本案例后续原牌谱作为指令；**被比较座位在第一步之后也交给同一套参考策略**，从而评价第一步的差异，不掺入用户后续操作差异。
4. 每条分支按规则运行到结算，以接手后的净得分作为收益 `R`。

```text
单个配对差值 d_i = R(a_user, W_i, 参考策略) − R(a_champion, W_i, 参考策略)
估计单步收益差 Δ = 所有 d_i 的平均值
```

只有第一步使用冠军牌谱中的动作，之后使用参考策略，因此基准应叫“冠军原选择＋参考策略续打”，不能叫“冠军本人模拟结果”。两种选择相同时，在同样确定性条件下配对差值应为零。

采用分别管理的牌墙与各座位随机流，记录规则、采样器、策略、随机种子及评估版本。相同种子并不意味着分支里每个人都摸到相同的牌；配对的是初始世界与随机条件，后续按真实规则分化。

与此不同，把全部真实暗手和原牌墙固定后进行模拟，是“这副已发生比赛的全信息反事实复盘”，不能替代上述只用 `I` 的决策评价。两类结果必须分栏标识。

牌谱优先模式也可以在同一原始状态和同一套补选规则下比较两个初始动作，但这只能得到“保留牌谱条件下”的对照结果。不能把带有本案例后续脚本的控制器混入独立策略评估，再将其区间解释为不知未来时的普遍优势。

### 7.4 置信度、预算与公允结论

每次评估事先确定样本预算、比较目标和有实际意义的差异阈值。默认报告配对平均收益差、95% 置信区间、样本量、积分单位和使用的策略版本。

- 区间整体为正时，可报告当前模型下有统计支持的收益优势；是否具有实际意义还要看预设阈值。
- 区间跨过零时，报告“暂时无法可靠区分”，不能把“没有检出差异”写成“两者一样好”。
- 如需宣布两者接近，应预先确定等效范围并通过对应检验，而不是临时调整标准。
- 候选筛选与最终确认使用独立样本，避免从大量步骤中挑最大值后夸大优势。
- 不在不断查看普通置信区间的过程中“算到显著就停”。首版采用预先固定样本预算；预算不足时保留不确定结论。
- 抽样误差变小并不消除模型偏差。评估器需经过规则确定的残局、人工审核题目与不同对手风格验证；结论随评估版本保存。

不完全信息博弈的评估研究也强调随机结果的方差问题。AIVAT 提供了相关方法依据，但本提案是配对模拟设计，**并未实现 AIVAT，也不继承论文中的准确度或样本节省效果**。[AAAI：AIVAT 原论文](https://ojs.aaai.org/index.php/AAAI/article/view/11481)

### 7.5 长期能力与产品成绩

首版不发布“超过冠军百分之几”或随意加权的百分制总分。成绩页先显示三个独立部分：本次实际结果、关键一步决策评价、后续训练建议。

后续能力评价使用多个未见案例、首次无提示记录和完整续打，报告平均净得分、亏损分布、规则错误、关键决策与参考策略的差异。不同底分可换算为底分单位，同时保留原始分数；不同案例的难度与相互关联需要在汇总时考虑，不能把同一副牌反复练习当作多个独立能力证据。

对手策略版本不同、使用提示、托管、断线恢复及重复练习分别记录。自由配置模型的练习不与固定基准挑战混排。公开视频案例不作为防作弊能力认证；将来如有正式排行榜，需要服务端核验完整记录、保留题和防止提前揭晓，不能信任客户端自行上传的成绩。

| 接手运行记录 | 来源检查点、个人摸牌优先／严格原牌墙／随机变式类型、牌谱优先／独立策略模式、用户动作、新事件、原动作匹配与补选原因、各座位摸牌游标与补牌来源、策略版本、提示与托管记录、接手前后积分 |
| 离线评估报告 | 候选动作、采样假设、独立样本批次、策略与规则版本、预算、收益和置信区间、人工复核结果 |
| 用户成绩 | 分开保存练习与首次挑战、实际结果与模拟评价；明确结果关联的报告版本 |
| 内容与发布记录 | 案例和关键步骤、脚本、成片、封面、文案及版本、素材交付和用户反馈状态、挑战版本与互链地址；用户手动发布后补充视频地址和BV号，投稿或审核状态仅按实际证据登记，未知字段留空 |

完整状态只进入有权访问的服务端和评估执行端。浏览器只获取当前视角所需数据，接口错误、日志、提示文本和模型上下文同样不得泄露隐藏牌。

### 9.2 Cloudflare 与本地使用同一套逻辑

继续保持 Harness 和模型会话在本地，牌局服务可部署于 Cloudflare 或本地。线上服务负责身份、案例读取、实时分支对战和结果保存；管理员本地批处理或独立评估进程负责大量模拟，审核后上传带版本与来源校验的报告。

Cloudflare Workers／Durable Objects 有执行时间、资源和存储限制，不应把大批量模拟放进正在处理牌局的同一个请求中。离线预计算是本项目的实现建议，不能承诺 Cloudflare 免费额度覆盖任意数量案例或评估。[Cloudflare Durable Objects 限制](https://developers.cloudflare.com/durable-objects/platform/limits/)

优先为精选案例预计算动作比较，用户点击讲解时读取已审核报告。避免每位用户每次出牌都触发成千上万次大模型调用。模型 API 费用与 Cloudflare 用量分别统计；评估器不可用时可以保留已验证回放与讲解，不伪造即时评分。

离线模拟使用受控的规则与策略执行器，按虚拟时间推进，不为每步真的等待 38 秒。实时练习仍沿用明确的超时和合法托管机制。

确定性基准应固定所有随机流与执行版本。需要调用语言模型的策略，应记录实际输出并支持重放；不能只凭温度设为零就承诺结果可复现。策略变更要形成新评估版本，不能悄悄改变已发布成绩的基准。

统一托管的正式成绩只接受受信任的评估产物或经过服务端核验的运行记录。本地自行运行的成绩可供个人学习，但不能未经核验就加入统一公开排名。

## 10. 素材使用与公开发布边界

以下按主要面向中国大陆用户设计，属于产品风险控制建议；具体赛事的权利归属与合同仍需逐案核实，不存在仅凭“用于教学”即可保证所有使用合法的通用办法。

著作权法区分单纯事实、具有独创性的编排以及视听作品；适当引用有条件，教学用途不是公开分发完整比赛素材的普遍豁免。因此不能简单认定“牌谱都是事实，可以任意搬运”，也不应一概认定每个落牌事实本身都需要许可。[《著作权法》第 5、15、17、24 条](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)

建议首版优先选择**权利来源清楚的结构化牌谱，使用自己的牌桌重现，并制作原创讲解**。这是降低不确定性的产品路线，不代表重画一遍即可免除所有来源、合同和平台使用义务。

| 对象 | 首版处理要求 |
| --- | --- |
| 数据及视频来源 | 记录获取与使用依据；需许可的内容向有权授权者取得可留档的许可，不以“公开视频可看”替代使用依据 |
| 授权范围 | 明确数据提取、保存、交互重现、讲解视频、发布平台、商业用途、期限地域以及能否向自部署用户再分发；未覆盖的用途不默认为允许 |
| 原转播画面、解说、音乐、台标 | 首版优先不用；确需使用时核对相应权利，注明必要来源，不把整段搬运包装成原创 |
| 选手名称、肖像、声音 | 区分客观赛事介绍与商业宣传；不暗示选手代言，不未经相应许可使用肖像或克隆声音，AI 对手不冒充真人 |
| AI 生成讲解与视频 | 发布适用的生成合成内容时，按适用要求及平台功能标识，不移除已有标识 |
| 分发与撤回 | 代码、教学报告、原始赛事数据各有自己的分发范围；授权到期或使用依据变化时，可停止相关案例分发 |

名称、肖像和声音使用还涉及人格权，应避免冒用与误导关联。[《民法典》人格权编](https://www.cac.gov.cn/2020-06/01/c_15925617772683193.htm) AI 内容发布者的声明义务及服务提供者适用的标识要求，见已于 2025 年 9 月 1 日施行的[《人工智能生成合成内容标识办法》](https://www.nrta.gov.cn/art/2025/3/14/art_113_70340.html)。普通确定性牌桌重放是否属于生成合成内容需看实际制作方式，不能把所有重放一概归类。

产品积分只用于学习和对局评价，不设置下注、现金兑换或输赢抽成；不用“稳赚”“保证击败冠军”等宣传。付费课程、素材再授权或正式商业赛事合作如后续新增，应根据实际业务另行核对，不能用本需求文档替代针对具体项目的审查。

## 11. 分阶段交付

| 阶段 | 交付结果 | 完成门槛 |
| --- | --- | --- |
| P0：完整牌谱与真实回放 | 一副已结束的冠军参赛牌局，来源、使用范围、规则和完整度明确，并在麻将实验室完整回放 | 历史过程必须完整、逐步合法、结算一致；余墙不足单独标识。片段教学不替代本阶段 |
| P1：关键一步教学 | 人工复核的精选步骤、首次作答、冠军原动作、备选与有依据的讲解 | 事实可回查，所有候选合法，不把未验证猜测写成定论 |
| P2：接续逻辑内部验证 | 独立分支、牌谱动作对齐与必要补选、个人摸牌优先、真实结算、原比赛参照和独立成绩 | 不偏离时复现已知原记录，偏离时按锁定模式推进；隐藏信息隔离、历史义务继承、分支恢复和结算验证通过 |
| P3：单步量化评价 | 固定版本的配对模拟、收益差和不确定性报告 | 同条件比较、保留样本验证、策略敏感性与专家复核通过 |
| P4：讲解视频与投稿素材交付 | 麻将实验室实际讲解录屏、配音字幕、封面、标题简介等完整本地素材包 | 音画、文件和结论检查通过，交用户查看；按反馈修改，分别记录制作交付与查看状态；不要求已在B站投稿 |
| 用户手动发布 | 用户查看后自行上传和投稿，决定账号、发布时间并处理平台审核 | 用户提供真实公开视频地址或BV号；我们不代为上传、保存平台草稿或投稿 |
| P5：公开挑战与互链 | 同一关键步的可玩挑战、结果对照、B站与挑战双向入口 | 用户发布视频后完成挑战公开上线，普通观众可玩完并查看可信评价；我们关联挑战页视频，用户手动更新B站入口，所有链接有效 |
| P6：扩充与能力训练 | 更多案例、辅助选题、未见题集和长期成绩 | 内容生产与评估可重复，不能靠背固定牌墙获得能力结论 |

首个完整线上闭环包含 P0–P5 和用户手动发布环节；P0–P3只是数据与技术基础，不能宣称整个新增需求已完成。P4制作交付通过后可以独立验收；用户暂缓发布时，继续挑战开发与内部测试，公开视频和互链保留为待办，不代为投稿。对外开放遵循第3.0节的顺序。自动批量选关键步骤、大规模比赛库、整场夺冠概率和课程商城属于后续扩展；通用无人值守批量投稿系统不在本次范围，本例视频的B站操作由用户完成。

如果完整赛事数据暂时无法取得，可以先用自有、明确标为教学模拟的牌局验证技术，但不能把它冠以真实赛事或冠军之名。

## 12. 验收条件

以下是后续开发必须验证的条件，本轮仅形成标准，尚未执行这些新功能测试。

| 编号 | 验收场景 | 通过条件 |
| --- | --- | --- |
| D01 | 导入缺失动作、暗手或余墙的数据 | 分别标记缺失项与可用能力；不能开启不具备数据条件的原牌墙续打 |
| D02 | 全副原比赛重放 | 每步合法、手牌和牌墙数量守恒、结算与来源一致，差异可定位 |
| D03 | 赛事规则与现有规则不同 | 阻止错误标注为原赛事规则；先适配或明确降级为改编练习 |
| D04 | 只有局部视频快照 | 不显示“已找出整副最关键一步”或“完整原局续打” |
| B01 | 用户改出另一张合法牌 | 对手优先沿用适用的原动作；默认个人摸牌优先按第6.6节执行，严格物理牌墙模式按真实墙序推进；均不机械执行失去触发条件的响应脚本 |
| B02 | 完整原状态已知，用户始终与冠军选择一致 | 默认牌谱优先模式重现原动作和结算，不因 AI 认为其他选择更优而擅自改写 |
| B03 | 接手前已有杠分，分支末触发退税 | 原付款关系被保留，退回金额与适用规则一致，并计入接手后净得分 |
| B04 | 分支有人已胡、碰杠改变轮次或发生流局 | 继承身份和规则状态，正确完成后续行动及终局处理 |
| B05 | 分支比原比赛持续更久 | 已知余墙按所选模式使用；缺失时明确标识固定模拟补全，不能承诺“完整原牌墙”或悄悄补造历史 |
| B06 | 刷新、断线恢复、重复提交同一动作 | 恢复同一分支，避免重复扣分和重复推进；原记录始终不变 |
| B07 | 原弃牌仍合法，但新变化未使其明显不适用 | 优先沿用原动作，不因微小估计收益差或原选手原有失误而无故替换 |
| B08 | 原牌已不在暗手，或原碰杠触发条件不存在 | 正确拒绝沿用，不补造牌张，不跨座位执行；从当前合法动作中补选 |
| B09 | 新摸牌、新副露或新的公开危险使原动作明显不适用 | 按当前座位利益补选，理由能关联到新变化；不为了帮助用户获胜故意放铳 |
| B10 | 一次补选后又出现适用的原记录 | 重新沿用该原动作；不可仅靠手牌相似就强制恢复历史轮次 |
| B11 | 新产生碰杠机会，或用户动作新增合法胡牌机会 | 进入正常响应流程并作策略判断，不因原谱没有相应记录而自动忽略 |
| B12 | 查看动作保留统计 | 沿用、替换、未匹配新增动作和跳过动作可核对，比例分母明确，不承诺固定保留率 |
| B13 | 某座位原定下一张牌已不可用 | 原摸牌优先模式沿该座位序列顺延；不取他人暗手、不复用实体牌，各张最多四枚且总数守恒 |
| B14 | 摸牌序列耗尽、额外杠补牌或刷新恢复 | 补牌规则、游标、牌池和种子固定可复现；正常响应与终局处理保留，记录补全来源 |
| I01 | 独立策略评估中保持可见信息相同，改变隐藏牌或未来牌序 | 该座位的输入视图不变；使用固定随机条件时，当前决策不因偷看隐藏数据而变化；牌谱优先的补选器还须固定同一参考动作进行隔离验证 |
| I02 | 未提交挑战前请求提示、日志或接口数据 | 不返回答案、他人暗手或后续牌；查看讲解后的记录正确转为练习 |
| I03 | 换三张等环节留下了该座位已知的私有信息 | 分支输入和未知牌采样保留这些观察，不漏掉选手本来知道的信息，也不泄露其他座位的私有观察 |
| E01 | 用户与冠军选相同动作 | 确定性配对评估差值为零，两条分支采用同一后续策略 |
| E02 | 某次差选择碰巧大赢、好选择碰巧亏分 | 结果分与决策评价分别显示，不按单次输赢改写决策质量 |
| E03 | 样本少、差异不明确、对手模型改变排序 | 显示不确定或条件依赖，不输出伪精确胜率、唯一最佳或超越冠军结论 |
| E04 | 重放同一评估任务 | 规则、种子、策略与记录输出可核验；模型输出不可复现时明确标记且不混入确定性基准 |
| E05 | 同一案例反复练习或看完公开后续 | 不被统计成多个独立盲测结果；公开资料导致的先验熟悉程度不被忽略 |
| E06 | 本地客户端上传伪造高分 | 统一托管的正式成绩拒绝未经验证的报告 |
| E07 | 比较牌谱优先接手与独立策略评估结果 | 分别标注条件，独立评估不读取本案例未来脚本；不能把脚本条件下多得分直接写成普遍优于冠军 |
| U01 | 在真实牌桌进入教学、提问与接手 | 保持原牌桌呈现；历史回放、讲解与新分支身份明确，问答不会更改原记录 |
| R01 | 某案例使用范围不含公开分发或已到期 | 对应发布／再分发被限制，仍可保留允许范围内的管理记录 |
| P01 | 在线服务同时处理对局和查询报告 | 大批模拟不阻塞实时动作与超时；资源不足时有清楚降级说明 |
| V01 | 生成讲解成片、字幕、封面和文案 | 同一案例与步骤、推荐和数值一致；真实麻将实验室画面可辨，原片与模拟画面不混淆 |
| V02 | 素材交付与用户手动投稿 | 完整本地素材供用户查看和自行投稿；我们不上传或创建平台草稿，内容认可不视为代发授权；制作无需账号信息，发布关联信息按用户提供的结果与公开证据登记 |
| V03 | 用户发布视频后上线挑战 | 入口可访问、挑战可打完、结果可核对；挑战页已关联视频，用户已手动补入B站挑战入口，双向链接有效 |
| V04 | 看完B站讲解的用户首次进入挑战 | 标记已看讲解的练习或未知熟悉度，不冒充首次盲测能力成绩 |
| V05 | 用户尚未发布或暂缓发布视频 | 制作交付和挑战内部测试可独立验收；未有证据的投稿、审核和公开状态保持未知，不为完成互链而代为发布 |

## 13. 首例选题时需要补齐的信息

文档采用的默认方案已经明确：先完成整副历史牌谱与真实回放，再选题、录制讲解、交付投稿素材，由用户查看并手动发布视频，再开放接手挑战；挑战开发与内部测试可提前进行。用户接手且其他座位采用“牌谱优先、必要时补选”，四家摸牌默认尽量沿用个人原序列。站内可先盲选再讲解，B站引流用户已看讲解的情况单独记录。单副预期净得分仍是主要决策指标，但使用不读取本案例后续脚本的独立策略评估，和牌谱优先练习结果分开呈现。

制作第一个真实案例时，需要分阶段确定：

1. 哪场赛事、哪位冠军、哪一副牌，以及冠军身份与赛制的正式依据。
2. 现有的是完整结构化记录、主办方数据还是视频；有没有暗手与剩余牌墙。
3. 素材可用于哪些发布方式，是否允许交互改编、视频讲解、商业使用及向自部署用户分发。
4. 赛事具体血战规则与积分单位，是否需要考虑整场积分局势。
5. 挑战公开前确定实际公开地址和首次接入条件；用户手动发布视频后再提供视频地址或BV号以完成关联。制作阶段无需B站账号昵称或UID。

这些信息决定首例案例能开放到哪个级别，不影响本需求提案的交付。后续实现应以选定案例的数据与规则为依据，不能用未经核验的假设替代。

## 14. 本轮文档交付说明

本轮将本提案升级到v4，将内容制作与挑战完整流程文档升级到v2，并同步 README 和实施追踪。主要变更为用户查看后手动发布视频、独立记录制作交付与发布状态、取消制作前索取B站账号信息。P0–P5仍按实际进度保持未完成，没有修改运行代码、已部署服务、赛事数据或普通练习的计分行为，也没有执行B站投稿。
