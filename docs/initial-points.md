# 开局初始积分

在「麻将实验室 → 开新桌」的四个座位卡片中分别设置「初始积分」。血战到底、标准国标和从历史步骤新开的独立练习均支持；真人和 AI 使用同一规则。每席默认 10,000 分，允许 0–1,000,000 的整数，开局后固定。

牌桌显示当前积分；结算净输赢等于当前积分减去该席初始积分。初始积分不参与番型、赔付倍率、合法动作和托管决策计算，不设置破产退出或负分截断。输分超过起点时仍会显示负数。

## 数据与升级

- 开桌请求的每个 `seats[]` 可传 `initialPoints`。本地插件和服务端都验证范围；服务返回值必须与本地锁定的配置一致，否则插件拒绝启动。
- 新表创建时将默认值写入座位元数据，随后通过已有的 `startBeans` 接口传给原牌局引擎。血战记录 `initialBeansBySeat`，国标记录 `initialPointsBySeat`；无需改变原牌桌绘制或计分代码。
- 新字段在本地会话存储中是可选字段。升级不迁移旧记录：旧表元数据缺失该字段时仍从 0 分开始，进行中牌局从持久化快照恢复，重连不会重设分数。
- 从历史步骤另开练习时，沿用服务器保存的牌序和局面，使用新开桌设置的积分。练习同时重设座位起点、当前积分、结算基准和流水，保留原牌局与牌谱不变。
- 先更新 Cloudflare 服务，再更新本地插件。只有客户端新增字段而服务未升级时，新请求会被旧服务拒绝。

## 代码审查与验证

修改涉及开桌面板、请求校验、服务连接、会话存储、权威开局和独立练习初始化。原前端素材、原渲染代码、原计分引擎和 Harness 核心保持原样。

验证覆盖默认值、自定义四席积分、非法值、服务返回值不一致、旧零分牌局、部分入座后的恢复、重复入座、独立练习、真实 Worker 请求与存储重启。血战和国标的完整对局逐笔核对流水与最终积分，检查总分守恒以及结算基准。

## 回滚

仅想恢复原来的零分玩法时，新开桌将四席初始积分设为 0 即可，无需回滚程序或更改数据库。若必须回滚程序，先结束本版本新建的进行中牌局，再将服务和插件一起回滚到上一版本；旧版启动尚未全部入座的新表时可能将后入座者设成 0 分。回滚前备份本地配置和会话；不删除或重建云端 Durable Object 数据、签名密钥或牌谱。
