## 已接通的链路

侧栏底部 **AI 麻将桌 → 打开案例复盘 → 在原生输入框提问 → 顶部切换三个案例步骤**。新建的空会话仍采用 Harness 的欢迎页；发出第一条问题后显示会话标题与步骤按钮。已有案例可从会话列表恢复。

本次是 `case-tianfu-20260706-8-8` 的三个精选时点，不是完整赛事牌谱导入器。原 `/hand/` 渲染 LC 已核对的牌；未知三家手牌、牌河、牌墙不生成。其他座位积分与余牌显示 `--`，头像声明为占位。画布保持 1280×720、16:9 等比缩放。

每个时点使用独立的原生 Harness 会话，保存固定步骤绑定。回到旧会话仍读取旧时点，迟到回复不会成为另一时点的回复。新的分析模型不被标作赛事玩家。分析上下文明确中文花色与听牌定义，并禁止将缺少余牌数误解成无法判断牌型。

## 案例证据与解释边界

来源：[用户授权的赛事录像](https://www.bilibili.com/video/BV1dJTR6YEFT/)，下半场 P4，本机文件后缀 `(3).mp4`。节目画面时间与文件时间可能约有 1 秒偏移，以下按文件时间定位。

| 时点 | 录像证据 | 插件展示与可核对结论 |
| --- | --- | --- |
| 33:59.5，摸牌前 | LC 立牌二条、四条、六条×2、七条×3；副露一条杠、八条碰 | 仅补三条成胡：234 / 66 / 777，加两组副露；杠四张只算一组 |
| 34:01，摸入三条 | LC 摸入三条，随后出现自摸/清一色表现 | 增加已知摸牌，不提前注入后续分数 |
| 34:15，自摸后记分 | 本副变化 +50 / −18 / −16 / −16；此前杠后变化 +2 / −2 / 0 / 0 | 自摸这一笔 +48 / −16 / −16 / −16；LC 原黄色 −18 加本副 +50 得 32 |

本副前黄色栏：LC −18、小智 3，相差 21；同期总局分 LC 33.7、小智 33.4，是另一种口径。不得把 +50 当 50 番、每家支付 50 或未经核验的最终赛事积分。片中算式是录像数值前后核对，不是插件规则引擎重新结算。

其他暗牌、完整副露、精确余牌和冠军判定公式未还原。因此不能从该案例继续实战、计算精确胜率或证明此前打法最优。

## 新增字段的含义与落点

| 字段/模块 | 白话与最小例子 | 收益与影响 |
| --- | --- | --- |
| `mode: "case"` | 控制器向插件区分本次局部教学，例如 `game.mode === "case"`；`/hand/?mode=case` 进入专用只读分支 | 不误走实时游戏连接；影响展示/问答，已加测试；不是完整 `paipu` 的替代 |
| `eventIndex` | 本案三个精选快照的数组下标，例如 `{eventIndex: 0}` 是摸牌前，不是整场第零手 | 同步视图和问答，拒绝非整数/越界与改绑；影响上下文，已加测试 |
| `partial: true` / `caseStudy.partial` | 明确只还原局部，例如 `caseStudy: {eventIndex: 0, partial: true}` | 关闭依赖完整局面的规则、流水、练习、荐牌与余牌推断；影响 UI，已加测试 |
| 存储 `caseStudy` | 现有会话记录增加可选 `{gameId: "case-tianfu-20260706-8-8", eventIndex: 0}` | 重启可恢复，且不送进实时游戏恢复；影响恢复路径，已加正反例测试；未改 SQL schema、未迁移旧数据 |

## 已知限制与风险

- 仍是 **Harness + dsh-mahjong + MJAI 联调**；未完成无 MJAI 干净环境交付。
- 只有一个案例、三个精选时点；未新增通用导入、导出、分享、练习或教练功能。刷新后从原会话恢复绑定有效；当前客户端步骤缓存是内存级，刷新后重新点击其他步骤可能新建会话。
- 原生问答可取消；模型/API 错误沿用 Harness 展示。**本轮没有新增问答总时限**，不宣称 38 秒出牌时限也是问答时限。案例加载有 15 秒错误提示；问答总时限与自动取消仍须后续独立确认。
- “只读”指案例视图和源数据，不代表关闭整个 Harness 的现有工具权限；原生会话仍遵循其访问模式，不改变主产品权限设置。
- 原有浮桌在部分窗口高度下会挡住上方消息。此次录制用 1440×720 窗口使答案区可读，未扩大范围重做全高度消息避让。新空会话标题/步骤入口首问后出现，仍是后续可优化点。
- 服务端游戏、规则结算与已有私人牌谱鉴权未改；本轮未额外打一整局实时游戏，不把现有回归测试称为全产品验收。

## 变更清单、部署和回滚

根因：原有实时快照不具备历史时点绑定；录像也没有可直接续玩的完整牌谱。本轮增加经过核对的局部适配，而不把缺失信息填成完整游戏状态。

本仓库产品/测试文件：`client.js`、`lib/teaching-case.js`（新增）、`lib/game-controller.js`、`lib/http-api.js`、`lib/session-game-store.js`、`test/teaching-case.test.mjs`（新增）、`test/game-controller.test.mjs`、`test/http-api.test.mjs`、`test/package.test.mjs`。

MJAI 产品/测试文件：`src/partial-case-runtime.ts`（新增）、`src/hand.ts`、`src/types.ts`、`src/center.ts`、`src/hand-hud.ts`、`src/world.ts`、`tests/partial-case-runtime.test.ts`（新增）。视频脚本、字幕、声音、实录和成片独立放在 `vides/dsh-mahjong-ep01-2026-09-06/`，不是插件运行依赖。未改 Harness 核心、模型密钥、项目依赖或游戏服务端；配音依赖仅装在系统缓存下的隔离环境。

部署：仅为加载服务端插件代码重启了本机专用 Harness；未重启 MJAI 前后端，未中断其他工作区服务；未提交或推送 GitHub。

观察窗口：首轮人工试用及后续三次启动，检查案例加载错误、错步回答、重复会话、原有游戏恢复。若出现错局/未来信息或影响游戏，应暂停案例入口。

回滚：优先撤回 `client.js` 的案例入口和案例步骤注册，保留原游戏入口、已存在的会话记录与只读恢复分支；这能停止新增案例而不把案例记录误当实时牌局。彻底撤回时逐项反向撤销本轮 case 相关改动及新增测试/适配文件，再重启专用 Harness。不要使用整仓 `reset`、覆盖整个脏文件、删除已有用户会话或数据库；如记录仍含 `caseStudy`，必须先保持恢复时跳过它们，不能直接删除识别字段。

文档同步入口：[模式需求](product-modes.md)、[视频录制](recording-workflow.md)。最终 MP4 及逐镜头时间线见维护者本机视频目录的 `README.md` 与 `timeline.json`。
