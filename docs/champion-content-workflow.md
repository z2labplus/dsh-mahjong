## 1. 最终要完成什么

先把一副真实比赛完整整理成可信牌谱，在 **dsh-mahjong「麻将实验室」** 中从开局回放至结算，再挑选关键一步，用同一张真实牌桌解释应该打哪张牌、其他选择有什么区别以及为什么。将讲解录制成视频，制作对应的文案和封面，交给用户查看、提出修改意见，再由用户自行决定何时手动发布到 B 站。随后在麻将实验室发布同一步的接手续打挑战，让观众亲自打完，并获得与冠军原局结果和原选择的对照评价。

执行顺序固定为：

**完整牌谱 → 麻将实验室完整回放 → 关键步与弃牌分析 → 麻将实验室讲解和录制 → 交付成片、文案和封面 → 用户查看并手动发布B站视频 → 接手挑战发布 → 视频与挑战互相链接。**

制作计划、录像片段或截图不能代替完整牌谱、回放与成片。经检查的完整素材包交付后，可记为“制作交付完成，待用户查看”；“用户手动发布”和“公开挑战及互链”分别记录，不能因素材交付就宣称整个线上链路已完成。

首个案例控制范围：**一副牌、四家完整记录、一个主讲选手、一个精选关键决策、一个讲解视频、一套投稿素材、一个可玩挑战。** 全量记录四家的动作；讲解重点放在主角的决策，不要求同时给四个人各制作一套深度课程。

## 3. 什么才算“完整牌谱”

本链路要求的完整牌谱是：**这副比赛实际发生的全部历史过程能够恢复**，包括四家起手牌、适用的换三张和定缺、每次摸打、响应与胡牌，以及最终结算。每个历史动作有来源证据；看不清时，只有能够从前后状态唯一确定才可补入，并标明推导依据。

“录像有开头和结尾”不能直接通过此项。机位切换、遮挡、视频剪辑造成的动作缺失，须逐项核实。若仍有多种可能，保留缺失记录，继续补证或另选一副，不能把示范片段升级成完整赛事牌谱。

需要分开记录两项完整性：

- **历史过程完整性**：决定能否准确回放全副、扫描全副选题。
- **接手后可用的隐藏状态与牌序**：决定能否延续原始牌墙，或只能进行明确标识的改编训练。原比赛没摸到的牌，不能因前面的动作已完整就假定顺序已知。

赛事积分按真实单位、底分和结算规则保存。普通新开桌的每人 4,800 分不覆盖赛事记录；如展示换算分数，必须同时保留原分和换算方法。

## 4. “冠军”及主讲选手

“冠军”必须有正式赛事结果依据，并注明是个人冠军、队伍冠军成员或其他确切身份，不能混用。一副牌净赢最多的选手只能称为“本副得分最高者”。

先核对已选场次中是否有符合定位的冠军选手；没有则从其他场次补选。也可把普通选手的案例做成“高手关键一步”，但这属于标题与定位的调整，不能悄悄替代用户要求的冠军案例。

必须区分原选手实际弃牌、我们分析出的理由和模型推荐。推荐可以与原选手不同；不为了宣传冠军而强行证明其每一步最佳，也不为了吸引点击而把模型分歧称为冠军失误。

## 5. 关键步讲解与视频

### 5.1 必讲内容

1. 这是哪场比赛、哪一副牌、哪位选手，当时处于什么局势。
2. 暂停在弃牌之前：主角有哪些牌、什么定缺、哪些公开弃牌和副露、谁已胡、还有多少牌及当前积分。
3. 请观众先选，再揭晓原选手的选择和我们推荐的选择。
4. 展示全部合法弃牌，并重点比较两到三个有教学价值的选择。按牌形、进张或听牌、潜在收益、放铳及流局损失解释。
5. 用麻将实验室逐步展示候选牌形变化和相关回放。展示假设分支时明确标为模拟，不能混入真实牌谱。
6. 给出推荐及其条件，说明相近选择、不确定性和一条可迁移到其他牌局的判断方法。
7. 邀请观众接手续打挑战；在完整发布链路完成后提供有效入口。

概率、收益差和结论引用同一个版本的评估报告。依据不足时使用定性解释，不凭语言模型的表述生成“胜率提高百分之几”等数值。若赛制目标是晋级或夺冠而非本副得分，须具备相关赛制与总分背景后再评价。

### 5.2 录制与成片默认方案

首版默认中文、横版 16:9，优先输出 1920×1080 的成片；牌桌仍按现有 1280×720 坐标等比显示。录制真实 dsh-mahjong 回放、讲解和必要的操作过程，沿用麻将实验室品牌及已有 MJLab.ai 标志。需要放大牌面或标注时保证牌张不失真、关键公共信息不被遮挡。

旁白和字幕必须与画面中的步骤同步；音量可听清，播放、暂停、跳转后仍能理解。时长服从讲清一个关键点，不为凑时长加入其他无关牌局。默认由中文讲解配音和字幕完成，不克隆选手声音。实际真人配音或合成配音方案随制作资源确定，并记录适用的平台声明。

原转播用于核对事实。发布成片以自己的麻将实验室画面和原创讲解为主体；确需使用原转播、声音或肖像时按配套提案第 10 节登记使用依据。

## 6. 投稿素材交付与用户手动发布

一条视频配一套可直接投稿的素材：

| 产物 | 内容要求 |
| --- | --- |
| 成片 | 已检查的录屏讲解视频，保留本地版本和文件校验值 |
| 封面 | 麻将实验室品牌、准确的关键手牌或候选弃牌、一个清楚的问题；与实际内容一致，不虚构冠军背书或保证获胜 |
| 标题 | 说明赛事案例和决策主题，避免用一次模拟获胜宣称整体水平超过冠军 |
| 简介 | 案例背景、主要知识点、来源、规则和评估条件；根据挑战是否上线使用准确的引导文案 |
| 标签与分区 | 提供符合实际内容的建议，用户投稿时按平台当前可选项选择 |
| 字幕与章节 | 与最终成片一致，标出局面、候选比较、揭晓、挑战介绍等内容位置 |
| 评论引导文案 | 指向同一案例挑战，交由用户按实际平台功能手动使用 |
| 素材清单与查看状态 | 文件名、素材版本、检查结果、用户反馈和修改记录；明确当前是否已交付、是否待用户查看 |
| 发布关联记录 | 用户手动发布后，根据用户提供的信息和可核验的公开页面登记视频地址、BV号及对应素材版本；未知字段留空 |

用户最新要求是“视频先不用发布，我查看后再手动发布”。我们的制作交付包括成片、封面、文案、字幕和相关说明，均先保存在本地交付用户查看。收到修改意见后更新本地素材；用户认可内容也不等于授权我们代为投稿。

B站账号选择、登录、上传、创建平台草稿、投稿、审核处理和后续改稿或评论由用户本人操作。制作阶段不需要用户提供账号昵称或 UID；先前索取账号信息的要求取消。素材说明中写明实际配音与画面的制作方式，供用户投稿时选择适用的声明。

状态分为“制作中”“素材已交付，待用户查看”“按反馈修改”“用户已手动投稿／审核中”和“用户已公开发布”。投稿、审核与公开状态仅按用户提供的信息或可核验页面记录；未取得发布结果时保持未知，不把本地交付写成已投稿。用户暂缓发布时，制作与内部开发仍可完成，公开互链单独保留为待办。

对外仍按视频先发布、挑战随后开放的顺序。挑战尚未开放时，给用户的简介文案明确“挑战开放后在简介补充入口”，不写“点击即可玩”。用户发布后提供视频地址或 BV 号；挑战通过验收后，我们在挑战页关联该视频，并交付真实挑战链接与补充文案，由用户手动更新B站简介或评论。预留二维码或固定案例地址时，目标页面也须准确显示开放状态。双向链接都有效后，才标记线上互链完成。

## 7. 接手挑战怎样玩

挑战由 dsh-mahjong 从**已核验牌谱中同一个关键决策之前**生成，不是重新随机开一桌。用户接管主讲选手座位，可选择任意合法弃牌，并继续操作至本副结束；遇到超时或选择托管时保留相应记录。

沿用用户已经表达的偏好：

- **其他三家的动作尽量贴合原牌谱**：原动作仍适用则执行；缺少原牌、触发条件变化或新局面需要调整时，按该座位利益补选，之后仍尝试沿用原谱。
- **四家的摸牌也尽量对应原来的个人摸牌顺序**：服务端优先取该座位原定的下一张可用牌；那张牌已不可用时，顺延该座位原记录中的后续摸牌。遇到额外摸牌或原记录耗尽，使用预先固定且标识清楚的补牌方案。
- 这是“原摸牌优先”的改编训练。不能从他人手中取牌、复活已打出的实体牌或制造第五张同名牌；必须维持 108 张牌的数量守恒及合法的碰杠胡、轮次和结算。原墙真实顺序、个人摸牌序列、补牌来源分别记录。
- 若改用严格物理牌墙模式，则碰杠导致摸牌人变化是正常结果；这一模式必须单独标识，不能作为用户上述默认要求的替代。

详细分支、取牌与补选规则见配套提案第 6 节。所有与原谱不同的动作和摸牌都有原因记录；原谱保持只读。原谱优先练习使用历史参考，不冒充另外三位真人在新局面中的真实反应。

如果分支用到了未知余墙的生成补全，应标为“已知历史牌谱＋模拟余墙”，固定生成方法和随机种子。该案例可以作为清楚说明条件的训练，但不能承诺严格原牌墙复现。历史本身仍不完整时，本链路第 1 阶段不能通过。

统一部署版在公开地址提供挑战；自部署版使用同一规则和案例版本。观众入口说明当前要求的账号、客户端或邀请条件，避免把需本地安装的流程宣传成免安装直玩；任何必要的首次接入步骤都要能实际完成。

## 8. 怎样告诉用户“打得好还是差”

不能只看一次最终赢钱，也不能只按是否胡牌评分。成绩页回答三个具体问题：

| 维度 | 比较内容 | 显示方式 |
| --- | --- | --- |
| 本次续打结果 | 用户从接手到最终结算的净得分，与原选手在原谱同一步之后的净得分相比 | 多得、少得或相同多少分，并标明这是本次分支结果 |
| 关键一步质量 | 在当时可知信息下，以同一批隐藏局面、同一套后续参考策略成对评估两种弃牌 | 模型条件下更有利、较不利、同一选择或证据不足；显示估计差异和不确定性 |
| 后续操作 | 分支中用户实际遇到的新局面，与固定参考策略比较 | 标出可改进的步骤和理由；不虚构冠军在该新局面里的真实选择 |

“本次比原局多得分”与“关键一步估计更优”允许出现不同结论。首次挑战、看过视频或答案、提示、托管、重复练习分别记录。看完B站讲解再来挑战属于已看讲解的练习，不能作为盲测能力认证；未知是否看过时，也不能仅凭第一次打开网页就认定未看过答案。

公开传播可以用“这一局你能打得更好吗？”作为问题，但结果限定在本案例、本条件下。整体水平、长期能力及“超过冠军”需要另外的未见案例与多局证据，本次首例不做这种承诺。

## 9. 一个案例必须能追溯到同一份数据

每个案例有固定标识，并关联：来源文件与时间区间、规则版本、牌谱版本、主讲座位、关键步骤、评估版本、讲解脚本、成片、封面、投稿文案、B站 BV 号、挑战版本和公开入口。

导入牌谱或规则发生更正时，检查已发布视频和挑战是否受到影响；有影响则更新、更正或暂停对应挑战，并提供视频修订素材和更正说明，由用户操作B站内容，保留版本关系。视频尚未更正时，挑战页须说明差异或暂停关联，不能继续用旧视频中的分数和答案误导用户。

原始长视频和私有检查点保存在本地素材区；可公开的代码、案例数据、视频和文案分别按各自使用范围分发，不把整个本地目录打包进安装包。录制和大批评估可在本地完成，Cloudflare 负责可公开的案例与挑战服务；不要求把完整原录像上传到 Cloudflare。
