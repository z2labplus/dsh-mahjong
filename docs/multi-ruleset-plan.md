## 1. 玩家将如何开桌

目标是：**同一张真实 `/hand/` 牌桌 + 多个规则集 + 自由配置 AI**，不是每种麻将分别安装一个 Harness 插件。

1. 在 Harness「设置 → 模型」配置可用供应商、模型与 API 凭据；插件不另存模型密钥。
2. 点击第一栏底部、设置上方的「麻将实验室」。
3. 选择已开放的麻将玩法，再配置该玩法支持的选项。
4. 配置四个座位的真人/AI 类型；AI 座位从可用模型中选择，允许同模型或不同模型。保持默认 38 秒、可配置的出牌超时。
5. 开始后整桌锁定玩法及选项，保留每个 AI 的独立会话和单独的玩家问答会话。
6. 提问、恢复牌局与复盘使用同一局规则；换玩法必须新开一局，不能中途切换。

上述包含尚未实现的玩法选择步骤，不能用来描述今天的操作入口；当前开桌方式以 README 为准。只开放通过验收的玩法，不把候选玩法名称做成可启动的选项。

## 2. 三个独立部分

| 部分 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 规则集 | 牌组、阶段、合法动作、胡牌、计分结算、终局与相应超时回退 | 不管理模型 API，也不由 LLM 临时编造规则 |
| 座位与模型 | 真人/AI 选择、模型目录、每席会话和调用 | 更换模型不改变全桌麻将玩法或结算 |
| 牌桌与 Harness | 真实 `/hand/` 展示、原生问答、外围开桌及大小/栏位切换 | 不重画牌桌、不修改 Harness 核心、不代替游戏服务裁决 |

**规则集（Ruleset，玩法规则包）**是“一种麻将规则的服务端模块”。抽取来源是 MJAI 已有 `server/blood-engine.ts` / `server/guobiao-engine.ts`；最终落点是 dsh-mahjong 自身交付的游戏服务与规则模块，以及插件的开桌、AI 和问答接入，不把规则计算留在必须另行部署的 mjai 服务中。

字段例子沿用现有代码：`match.conditions.gameType = 'BLOOD_BATTLE'` 表示血战，`'GUOBIAO'` 表示国标；插件 `seats[1].kind = 'ai'` 和 `seats[1].model` 只决定第二席由谁来打。这不是新增开桌 API 的请求样例，当前插件请求还没有玩法选择字段。

收益是共用牌桌、会话与传输，隔离玩法差异，降低串规则与重复开发的风险。未来实现会影响核心合法性、状态机、结算、AI 输入与复盘，因此必须落到代码并用正反例测试验证；本次文档本身不改变运行行为。新字段、接口签名和规则版本保存方式留到技术口径确认后再定义。

## 4. 实施顺序与不变边界

1. **血战模块化**：整理已有规则的公共调用边界，保持现有规则、计分结算、回退和界面行为不变。
2. **国标接入**：复用已有引擎，完成玩法选择、合法动作、AI/问答上下文、恢复、牌谱与复盘，实际跑通第二种玩法。
3. **广东等扩展**：逐个确认具体规则规格，再实现和验收，不因同名玩法而推定其番种、花牌或计分方式。

上述是玩法扩展的先后关系，不替代独立交付要求；具体抽取与接入排期另行确认。每个对外宣称支持的玩法，都必须在没有 mjai 仓库或服务的独立环境中通过完整链路验收，不能只在现有 mjai 联调环境跑通。

原样复用 `/hand/` 的牌面、桌布、布局、动画、声音与 1280×720 等比 `contain`。保持官方 `shell.overlay`、默认两栏、第一栏底部入口和原生问答；同局的一/二/三栏及大/紧凑切换不重建 iframe，不丢失牌局。“提问这一步”的紧凑高度仍默认取第二栏可见牌桌区的 50%，受栏宽限制时等比收敛；牌桌本体仍无圆角、边框、阴影或裁切。新玩法确需专属按钮或提示时，单独确认后适配，不重画另一张牌桌。

本次不扩大到三人/十六张布局、跨玩法自动匹配、另一套模型凭据管理或任意上传执行规则代码，也不改动 Harness 核心、支付、账号或 iPhone 原生应用。

## 5. 编码前确认与上线门槛

编码前确认具体模块、规则差异表、合法动作、阶段/结束分支、计分、超时回退、AI/问答输入字段、旧局恢复策略及必要的专属 UI 改动。设计方向不替代这些高耦合口径，也不替代逐次授权。

每种玩法开放前必须验证：

- 四人全真人、3 真人 + 1 AI、2 + 2、1 + 3、全 AI 五种组合，各完成至少一局；模型选择不改变玩法。
- 正例：血战行为保持不变；新增国标桌的合法吃牌、胡牌、结算符合已确认国标规格。
- 反例：血战拒绝吃牌；国标拒绝血战专属定缺/换三张；过期、跨局动作和局中改规则不能改变当前状态。
- 超时与断线恢复使用该玩法规则；问答、恢复、牌谱和复盘保留本局玩法及选项，不静默回落到血战默认值。
- AI 只能看到本座暗牌与公共信息；问答不扩大原有授权范围；所有动作继续由服务端验证。
- `/hand/` 外观、关键交互、16:9 缩放与同局 iframe 连续性回归通过。
- 最终开放玩法随 dsh-mahjong 自身交付，在无 mjai 源码、服务、数据库和凭据的环境中通过同样的对局、恢复及复盘验收。

风险是不同规则的同名动作、结束条件或计分被混用；实施必须以规则差异表和固定场景测试收敛。每次交付须说明改动文件、验证结果、观察指标和文件级回滚；涉及保存格式或数据库变化另行确认兼容与迁移。本文件只记录后续需求，不改变 [M0 的已有验证记录](m0-acceptance.md)。
