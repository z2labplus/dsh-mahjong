## 1. 先明确分工

**dsh-mahjong 是真实教学牌桌和备课环境；外部录屏软件是摄像机；剪辑软件负责成片。** 第一阶段不在插件内开发视频编码、录音或剪辑器。

准备案例 → 获取真实牌桌画面 → 核对并审核讲解 → 录屏与配音 → 剪辑字幕 → 人工复核 → 另行授权发布。

同一个案例将来可对应三种交付：免费短视频、完整课程片段、可操作练习。MP4 是可观看的成品，牌谱/案例是支持定位和重复练习的数据；视频文件本身不能让插件恢复一手牌。

## 2. 目前有什么、缺什么

以下是源码与既有文档核查，不是本轮运行验收结果。

| 能力 | 证据与状态 | 对录制的影响 |
| --- | --- | --- |
| 真实牌桌和大/紧凑切换 | [客户端](../client.js) 有聚焦与“提问这一步”；[M0 清单](m0-acceptance.md) 已记录布局验证 | 可以作为屏幕素材来源；录制时仍需实测清晰度与声音 |
| Harness 当前牌局问答 | [控制器](../lib/game-controller.js) 的 `qnaSnapshot(sessionId)` 读取实时观战快照，并作为动态上下文提供给可见会话 | 不代表回答会锁定到鼠标点击时或回放选中的历史一步 |
| 原 `/hand/` 逐步回放 | MJAI `src/hand-paipu-runtime.ts` 有 `prev`、`next`、`currentEventIndex`；`src/hand.ts` 连接回放 HUD | 是可复用的基础，不表示 DSH 所有牌局已能通过现有入口取回牌谱 |
| 牌谱读取与分享 | MJAI `src/paipu-api.ts` 使用带鉴权的牌谱接口，`src/hand.ts` 回放入口仍调用用户校验 | DSH 牌局保存、访问权与完整数据需端到端核查，不能直接把旧分享链接当成独立插件课程入口 |
| 练习与教练基础 | MJAI 已有 `practice-*` 与练习存储/重建代码，以及 `src/coach.ts` 的幺九教学原型；牌谱到练习仍未完整接通 | 不是从零新增概念，也不代表已进入 dsh-mahjong；首条视频先不要求这些链路 |
| 插件内录屏、历史步骤定位/问答、课程导入 | [插件 API](../lib/http-api.js) 当前列出模型、状态、开局、重试与停止路由；未发现上述录制/课程接入 | 模式方向已确认，具体能力尚待接入，不宣称已有“一键录课”或“一键练习” |

关键区别：暂停录屏只停止采集画面；收起牌桌、停止 Harness 生成或停止某个 AI 会话，也不等于游戏服务暂停计时。不能拿这些操作实现“讲多久都不超时”，更不能修改血战超时规则来迁就录课。

## 3. 第一阶段：外部录屏，先做一个样片

推荐先做一个血战选择题的 60–90 秒样片，不直接录整局长课。

1. **备课**：只确定一个问题，例如“这手是否应该碰”；先由老师核对玩法、当时可见牌与解释。不得仅因 AI 这样打，就当作正确示范。
2. **采集素材**：在 Ego Lite 的专用 Harness 牌局中，用全 AI 教学局或已获授权的真人/AI 局采集真实画面。正式录制前确认画面和模型状态；全 AI 不意味着可任意访问其他私有会话。
3. **选定一步**：优先使用已经验证可访问的结束牌局回放。若 DSH 牌谱链路未通过，先从原始录像选取片段，并在剪辑中定格；这是视频定格，不是假装已经暂停或回退实时牌局。
4. **讲解后录**：先完成审核再配音。可使用真实且与该步一致的 AI 回复作辅助；历史问答未接通时，不在仍注入实时状态的会话中冒充历史复盘。必要时只用老师讲稿完成样片。
5. **剪辑与复核**：加入题目、思考时间、理由和总结；删去无关等待。预先生成、补录或剪辑的部分如涉及功能展示，应注明，不能宣称是实时响应。检查牌面、字幕、声音、授权与隐私，再决定是否发布。

课程例子：0–10 秒显示真实局面并提问；10–20 秒让观众先判断；20–65 秒老师解释选择依据；65–90 秒总结适用条件。案例没有完成审核前不填入确定推荐，更不虚构 AI 原本作出的选择。

## 4. 录制工具与构图建议

推荐先用 OBS 的窗口捕获录制 Ego Lite 中的专用 Harness 窗口，另录麦克风。OBS 官方说明其 macOS 捕获支持窗口/应用选择；系统声音支持与 macOS/OBS 版本有关，按当前设备核对后录一个 30 秒测试片，检查游戏音效、人声和是否重复收音。[窗口捕获说明](https://obsproject.com/kb/macos-screen-capture-source)、[声音说明](https://obsproject.com/kb/macos-desktop-audio-capture-guide)

| 录制画面 | 插件如何配合 | 后期如何处理 |
| --- | --- | --- |
| 讲牌 | 使用既有聚焦牌桌，按 16:9 放大真实 `/hand/` | 保留整桌；字幕、题目和品牌放在外侧，局部特写作为额外画面 |
| 讲解提问功能 | 使用既有紧凑牌桌，上方牌局、下方可见原生对话 | 只使用明确对应当前局面的问答；历史步骤未接通时不用于历史教学演示 |
| 总结与练习题 | 复用同一案例的已审核素材 | 外部添加总结与思考题，不伪造插件已有课程按钮 |

- 横版母版建议 1920×1080、30 fps，作为首轮试录参数，不是本机性能保证；原画面必须足够清晰，不能靠放大小窗口制造细节。先试录再调整窗口与采集尺寸。
- 竖版短视频可另排为 1080×1920：完整 16:9 牌桌置于上方，下方放题目和解释。改变的是视频外框，不把 `/hand/` 拉成长条，也不裁掉关键座位、手牌或动作来填满屏幕；在手机上检查牌面可读性，必要时增加独立特写。
- 可以裁掉浏览器标签栏、地址栏或私人会话区，但不改变牌桌本体。原始素材中若已录入秘密，应重新录制并安全处理原文件，不能只依赖成片打码。
- 录制前关闭通知与无关窗口；不要录入模型设置、API 密钥、邀请票据、支付信息、私人会话或未授权参与者资料。关闭或更换未经许可的背景音乐不能通过修改 `/hand/` 源码擅自完成，优先在录制混音中不采集该音轨并核查剩余声音授权。
- 可先录 MKV，再用 OBS 自带功能转封装为 MP4；这是兼顾中断恢复和编辑交付的建议，不等于插件导出视频。[OBS 录制指南](https://obsproject.com/kb/standard-recording-output-guide)

录制边界仍是本机实录与交付 MP4，不开放额外远程端口，不接上传或自动发布。已有内部样片由本机剪辑工具合成，并非 OBS 实机录屏验收；后续若需要新增工具、系统录屏权限或扩展自动化控制范围，单独说明，不用赛事素材许可代替这些授权。

## 5. 模式接入：让视频和可练案例对应（方向已确认，待实施）

长期结合点是“视频讲哪一步，插件就能定位、解释并练习哪一步”，而不是把 MP4 嵌进牌桌。

先用现有字段说明定位：`gameId` 是哪局，`eventIndex` 是牌谱事件数组中的位置，`seq` 是事件记录的序号，三者不可混用。示意 `{"gameId":"G123","eventIndex":42}` 指某局第 43 条数组事件，不是“第 42 手”；它不是现有开桌 API 已支持的请求，也不是可公开访问的课程链接。

| 待接入能力 | 项目落点与最小例子 | 收益、影响与验证 |
| --- | --- | --- |
| 固定步骤备课 | 复用 `/hand/` 回放与牌谱定位；选中上述 `eventIndex`，读取该时点已授权快照 | 不再等待实时对局碰巧出现同一局面；会影响显示与问答上下文，需用代码和正反例锁定事件含义 |
| 历史步骤问答 | 插件可见问答上下文绑定当前回放位置、规则与观察座位，停用该教学会话的实时状态注入 | 防止屏幕显示上一手而回答下一手；切步后的旧请求要取消或保留明确旧步骤标识，不混入新答案；拒绝跨局、越权与无效位置 |
| 案例导出与导入 | 在已有牌谱数据上制定独立、版本化且经过筛选的教学交付格式；内含重放必需状态/事件、玩法与许可信息，具体格式另行确认 | 本机 `gameId` 不能自动跨设备使用；干净环境导入须无需 mjai、原作者账号或私有链接，拒绝无授权内容与不兼容规则 |
| 从该步练习 | 依据已验证案例另开教学练习，不修改源牌谱或正在进行的真实牌局 | 学员不只看录像；涉及状态机、随机性、暗牌与结果比较，必须先确认规则/权限口径，不能把只读回放当成已能继续出牌 |

一份案例可以附对应视频，但不把录像或完整 Harness 日志当成可分享存档；不把模型 token 或所有席位私有信息打包。公开教学视角和玩家实战视角分开，是否展示全手牌必须有明确授权，不能因教学模式扩大其他 AI 座位的权限。

游戏、牌谱、练习与后续教练的产品方向已按 [模式需求](product-modes.md) 确认；上述具体接口、存档格式、权限与技术口径仍需在实施前确认。本次不为说明方案而新增真实字段、接口或 UI，也不授权暂停权威实时牌局、改核心规则、修改 Harness 核心或重绘 `/hand/`。

## 6. 最小验收与先后关系

1. 已有外部剪辑内部样片；最终实机录制前仍需完成真实页面音画测试、事实与讲解核对，不能用旧样片解码通过替代实机验收。
2. 产品继续保持游戏模式与独立运行路线；本片优先按批准范围接入单案例固定步骤回放和历史问答，再推进练习与后续教练模式，不把四种模式全部完工设为首条视频前提。
3. 历史接入验收正例：同一案例、同一步、同一观察权限下，画面与 AI 输入一致，切换栏位不改变步骤。反例：切步后迟到答案、错局位置、未来信息、未授权暗牌、跨设备无效引用均不得被当成当前正确上下文。
4. 成片验收：牌面可读、人声清楚、规则与解释审核通过、不泄露隐私；标明实录/复盘/剪辑的实际性质，不承诺已完成独立部署或一键互动。
5. 问答录制前覆盖取消、失败和超时可见性；历史回答不串步。具体问答时限尚待确认，不等同于游戏的 38 秒出牌时限。可以剪掉等待，但明确经过剪辑，不冒充实时响应速度。
