# 旧 MJAI 后端兼容层移除

日期：2026-09-07。用户要求移除兼容层，review 后提交代码库。本次交付包含此前尚未提交的独立前端、Cloudflare 服务、玩法与安装流程。

## 实际变更

- `index.js` 仅接收 `service`，删除旧 `mjai`、静态座位配置、旧状态工具及静态运行时生命周期。旧配置会在启动前明确报错。
- 删除 `lib/mjai-dsh-control.js`、`lib/mjai-seat-runtime.js` 及其旧包导出；当前模块为 `service-control.js`、`service-spectator.js`、`seat-runtime.js`，没有转发别名。
- 开桌和恢复统一使用独立服务 REST 接口，删除旧 WebSocket 开桌/恢复命令。AI 只使用座位凭证及内存中的恢复凭证，不再使用旧 API Token 入桌或客户端修改座位/昵称。
- 删除旧端口默认值、旧控制连接地址回退及旧返回字段回退。浏览器只使用独立服务验证过的会话，删除旧原始票据解析、旧入桌方法和 `autotable.playerId` 迁移。
- 更新默认配置、Cloudflare 示例、启动助手和测试。牌桌图片、字体、声音和模型素材均未更改。

真实牌桌的本地渲染、规则和传输适配仍由本项目提供。复用源码中的协议声明、原界面接口和来源注释不表示存在外部 MJAI 服务依赖；本次没有重绘牌桌，也没有删除来源许可。构建、安装和运行不读取外部 MJAI 工作区、账号或数据库。

## Review 发现与修复

1. AI 座位接管后旧连接仍会自动重试。收到服务接管关闭码后，旧运行时停止重连、取消当前模型决策并拒绝待确认动作；正常网络断线仍可恢复。
2. 恢复链路未完整核对返回的牌局描述。现在开桌与恢复均核对规则、座位种类、桌主、阵容唯一性、超时时间及恢复局号；缺失座位授权时拒绝启动。
3. 观战重连后的握手前缓存超限没有关闭连接。现在初次握手与重连都限制缓存，超限即丢弃缓存并关闭当前连接。
4. 浏览器会话重新验证失败时可能留有先前内存角色。验证前清空角色，失败后不能退回旧 URL 票据路径。

Review 覆盖插件注册、开桌/恢复、座位与观战连接、同源 HTTP 请求、凭证存储、邀请/分享边界、安装打包和公开文件清单。自动化验证使用真实本地 workerd、SQLite Durable Objects 和 WebSocket；模型运行时采用测试替身，不消耗用户模型余额。

验证结果：插件测试 102 项、服务测试 161 项全部通过；插件语法/包契约、前端和服务类型检查通过。558 个来源文件经过清单核对，477 项素材字节保持一致。发布包在全新目录安装依赖，并在禁止读取本机 MJAI 工作区的系统沙箱下成功构建前端及 Worker。专用 Harness 重启后，状态与牌谱接口均返回成功，无请求凭证的访问被拒绝；原 Harness 实例保持可用。待公开源码和发布包已检查，未包含实际部署密钥、使用者凭证、私有配置、日志或依赖缓存。

## 升级与回滚

这是旧 MJAI 配置和旧模块导出的破坏性移除。手工配置需改为随包的 `service` 示例；启动助手会自动生成新配置。原 MJAI 数据库中的牌局不会迁入本服务。

回滚时恢复升级前备份的完整插件源码及对应配置，重新构建并重启专用 Harness。保留 `.local/`、服务签名密钥和 Durable Object 数据；不要用删除云端命名空间的方式回滚。恢复旧接口也会恢复旧兼容代码，因此不再满足本次清理目标。

本记录对应源码交付，线上版本须以独立部署记录为准；推送 GitHub 不会自动部署 Cloudflare。
