## 审查结论

本轮发现并修复了两处用户操作问题，补齐回归测试后通过检查。当前审查范围内没有保留阻止提交的问题；这不代表赛事原谱已全部完成视频核验，或未开发的挑战能力已完成。

1. **全部撤销后可能恢复旧草稿。** 原逻辑在草稿等于正式记录时删除浏览器缓存，并跳过服务器草稿保存，重新打开可能恢复旧编辑。现在保留撤销后的当前内容、按序保存，同一编辑窗口优先恢复本地最新内容；与正式记录一致的草稿不显示为待恢复修改。关闭面板时也保存最新状态，网络失败时仍保留本地缓存。测试覆盖慢请求顺序、失败后继续保存、旧服务器时间戳，以及真实界面的保存→撤销→立即关闭→刷新→重开。
2. **已撤下讲解仍有可点击入口。** 案例目录现在明确返回是否存在讲解；没有讲解时禁用入口并显示“讲解待复核”，避免创建会话后才报告无效章节。

同时将新的嵌入构建目录加入 npm 排除规则，修正需求文档中过时的“尚未开发”和“完整视频已核验”表述；说明测试样例保留的旧误记用于回归，不能当作最新赛事原谱。

## 重点核对

- 保存以原谱为唯一事实来源；手牌、牌河、副露、余牌和本副积分统一生成。
- 失败校验不修改正式记录；草稿、基础版本冲突、原子文件切换、版本恢复和重复提交保持独立处理。
- 校验诊断比较草稿基础版本，关联建议不自动改动数据；关联摸打一次撤销／重做整组。
- 跟随视角取当前事件的行动玩家，旧问答固定在原步骤、座位和版本。
- HTTP 编辑接口保持同源和进程令牌检查，不接收浏览器指定的文件路径；静态资源限制在专用构建目录，检查路径穿越及符号链接逃逸。
- 原牌桌保持真实 `/hand/`、16:9缩放、已批准的昵称卡片及历史显示适配；不改Harness核心。
- 本地视频、账号配置、草稿、运行状态和构建缓存未进入提交。无新复制的第三方素材。
