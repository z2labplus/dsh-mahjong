## 1. 用户最终只需要什么

**终点：DeepSeek Harness + dsh-mahjong 即可独立完成麻将对局，不依赖 mjai 仓库或服务。**

在正常系统运行环境中，用户安装支持的 Harness 和 dsh-mahjong，在 Harness 配置自己的模型 API，即可通过「AI 麻将桌」开局、打牌、提问、结算、保存、恢复及复盘。游戏服务、规则、真实牌桌、获准资源及必要存储由 dsh-mahjong 自身交付、初始化和管理，不让用户另外搭建一套 mjai 或维护外部麻将后端/数据库。

“独立运行”不等于脱离 Harness、无需正常运行环境或 AI 离线运行。它排除的是对 mjai 的安装、构建、运行、私有访问和现存数据的依赖；内部组件是否同进程、采用何种存储或打包方式，仍需在实施前确认。

2026-09-06 补充：用户已确认游戏、牌谱、练习及后续教练模式，详见 [模式需求](product-modes.md)。**每个对外开放模式都必须满足本文件的独立交付要求**：案例载入、历史回放/问答、练习重建与保存、教练关卡不能隐式依赖 MJAI 的私有页面、账号或数据库。来源抽取仍保留许可与一致性记录；这不表示本轮迁入上述能力，也不要求首条视频前完成全部模式。

## 3. 必须保持的边界

- **无隐藏依赖**：不得要求克隆 mjai、访问其私有源码、软链接其目录或使用其 Git submodule；构建、安装、测试和启动不得后台下载 mjai 才能完成。
- **无服务回源**：不得依赖本机或远端 mjai 的规则接口、牌桌资源、前后端、账号、API 凭据或数据库。将本机 mjai 改成远程 mjai 代理不算独立运行。
- **自身交付完整能力**：规则集、合法动作校验、结算、超时回退、真实牌桌、必要存储与恢复、牌谱/复盘及其启动管理须随 dsh-mahjong 提供；无需用户额外维护第三套麻将服务。
- **真实 `/hand/` 不变**：抽取复用经许可确认的真实实现、递归依赖与资源，保持牌面、桌布、布局、动画、声音、交互、1280×720 等比 `contain` 和已确认浮桌体验，不使用仿制 UI 或截图替代。
- **来源与运行分开**：保留源版本、文件/资源哈希、许可与验证记录，MJAI 仅作为历史来源或维护者可选比对来源。标准用户和贡献者路径无需访问 mjai；也不因此公开整个私有 mjai 仓库或业务数据。
- **安全边界不放宽**：继续用 Harness 官方插件机制与模型凭据管理；独立游戏服务是状态和规则的唯一权威；保留每席暗牌隔离、动作校验、超时与独立问答授权范围。
- **许可冲突先确认**：无法独立分发的实现或资源先记录缺口、说明影响并取得用户决定；不擅自复制，也不擅自替换牌桌素材来绕过一致性要求。

## 4. 独立交付验收

**验收环境：没有 mjai 源码、依赖目录、进程、数据库与凭据；不允许连接 mjai 私有资源或接口。** 保留正常系统运行环境、Harness 和用户自行配置的模型 API。

| 验证项 | 通过标准 | 必须排除的反例 |
| --- | --- | --- |
| 干净构建与安装 | 仅获取 dsh-mahjong 的可分发源码或发布包及正常依赖，即可完成相应构建/安装 | 依赖开发机的 mjai 工作区、私有 Git 权限或残留构建缓存 |
| 启动与数据准备 | 由官方插件入口启动游戏能力，自行准备所需持久化环境 | 要求填写 mjai 服务地址、控制凭据或手工准备其数据库 |
| 完整对局 | 四人全真人、3 真人 + 1 AI、2 + 2、1 + 3、全 AI 五种组合完成开局到终局 | 只有插件入口能显示，实际出牌、规则或结算仍调用 mjai |
| AI 与问答 | 合法/非法动作、超时回退、当前局规则问答、暗牌与授权隔离正常 | 直接信任 AI 动作，或回源 mjai 才能提供合法动作和状态 |
| 保存与恢复 | 独立保存牌局，重启后恢复；牌谱/复盘保持原局规则、选项与座位/模型归属 | 从 MJAI 旧数据库读取必要状态，或恢复时静默切换规则 |
| `/hand/` 一致性 | 自身提供真实牌桌及资源，基准视觉和关键交互通过；同局栏位/大小切换不丢状态 | 页面看起来相同，但资源实际来自 mjai；或以重绘牌桌代替 |
| 隐藏依赖检查 | 保留构建、安装、进程、文件路径与连接证据；阻断 mjai 访问后以上功能保持正常 | 本机可用仅因另一份 mjai 仍在后台运行或安装脚本偷偷拉取它 |
| 开放模式覆盖 | 每个已开放的游戏、牌谱、练习或教练模式在该环境完成自己的访问、问答、保存/恢复及权限验证 | 游戏已独立，但牌谱、练习或教练仍须连接 MJAI；未实现模式被宣传为已支持 |

每种对外开放的玩法都必须在该环境验证；“血战模块化 → 国标接入 → 广东等扩展”的先后关系保持不变，具体抽取和接入排期另行确认。多规则集在 mjai 联调环境跑通不能替代独立交付验收。

本节是未来验收标准，不是本轮已执行或已通过的结果；既有 M0 结果仍按原清单记录。

## 5. 实施前确认与过渡退出

1. 先核查必需游戏能力、`/hand/` 递归依赖、来源许可与构建/存储依赖，明确可独立交付的范围。
2. 确认模块与打包方式、存储初始化/持久化、服务生命周期、旧局兼容及回滚；不自动选择数据库、强制单进程或将整个 mjai 搬入公开仓库。
3. 按批准范围抽取和接线，并验证规则、界面、AI 与恢复行为未因迁移退化；迁移涉及规则、鉴权或数据时，按对应风险与口径要求单独确认。
4. 在干净环境完成 §4，记录发布内容、验证证据、风险、回滚触发条件与步骤，再另行授权发布。

保留当前 mjai 联调路径的原因是独立交付尚未完成，暂用于迁移回归对照。退出条件是来源许可、干净环境验证及回滚/旧局兼容方案均通过；对外宣称独立交付前，必须清除标准安装与运行对 mjai 的要求。旧路径的实际清理需当次授权，不在本轮删除任何代码、配置或数据。

未来回滚应回到上一个可独立运行的 dsh-mahjong 版本；若只能回到 mjai 联调模式，必须明确撤回“独立运行”声明，不能隐藏恢复依赖。当前产品的实际限制继续在 README 顶部披露。

## 6. 分阶段实现路线（2026-09-05 同步，待实施）

目标是把必要游戏能力变成 dsh-mahjong 自身的可交付内容，不是将整个私有 mjai 搬入本仓库。推荐先完成血战的独立运行，再依次接入国标、广东等规则；可并行分析依赖，不能跳过各阶段的确认与验证。

| 阶段 | 具体工作与现有落点 | 进入下一阶段前的证据 |
| --- | --- | --- |
| 1. 确定抽取范围 | 核查 MJAI 的 `src/hand.ts`、递归代码/资源、`server/blood-engine.ts`、`server/server.ts` 的 DSH 对局处理、保存恢复及构建依赖；记录来源版本、哈希和许可 | 必需文件与许可缺口清单、抽取边界、当前行为基线；规则、鉴权和旧局兼容口径获得确认 |
| 2. 原样迁入牌桌 | 将真实 `/hand/` 与获准依赖/资源纳入自身构建和发布；接入现有 [牌局控制器](../lib/game-controller.js) 的牌桌地址与既有会话/浮桌承载 | 自身服务页面能独立加载；固定截图、声音、关键操作、16:9 缩放及同局栏位/尺寸切换保持一致，不回源 mjai |
| 3. 抽出游戏服务 | 迁入开桌、规则、合法动作、结算、超时与重连能力，接通 [桌主控制](../lib/mjai-dsh-control.js) 和 [AI 座位连接](../lib/mjai-seat-runtime.js)；解除 MJAI 账号及无关业务耦合 | 合法动作正例和非法/过期/重复/跨座请求反例通过；桌主、座位与暗牌权限没有因脱离 MJAI 而消失；原血战行为对照一致 |
| 4. 独立保存与启动 | 自身管理游戏组件启动、就绪、停止与失败处理，替换启动脚本的外部 mjai 路径；为牌局、座位、牌谱提供自身存储与初始化 | 不要求外部 mjai 地址、数据库或凭据；新局可保存并在重启后恢复；旧局迁移/兼容与回滚按已批准方案测试，异常退出可定位且不遗留失控服务 |
| 5. 血战独立验收后扩展 | 在 §4 干净环境完成五种混搭的完整血战、问答、终局和复盘；通过后再推进 [多规则集计划](multi-ruleset-plan.md) | 构建/安装/运行和隐藏依赖检查通过，记录回归结果及发布/回滚条件；每种后续开放玩法重复独立验收 |

阶段 2 的页面验证与阶段 3 的规则对照可以使用明确标注的过渡测试环境，但不能当成独立交付通过；最终必须同时替换页面资源、游戏服务和数据依赖。

### 6.1 三处容易遗漏的耦合

- **牌桌不止入口文件**：MJAI `src/hand.ts` 还连接 HUD、声音、牌谱、用户资料和 WebSocket；`src/hand-hud.ts` 有练习与分享入口。必须追踪真实依赖并确认对应行为，不能只复制入口或删除按钮来宣称一致。
- **规则不止两个引擎文件**：MJAI `server/server.ts` 同时连接账号、支付和其他业务。仅抽取游戏必需部分，不能整包带入，也不能通过取消权限校验来解除耦合；权限改造属于高风险，需单独确认。
- **会话映射不等于完整存档**：现有 [会话映射存储](../lib/session-game-store.js) 保存会话与牌局关联；实际牌局/席位、活跃状态和牌谱还涉及 MJAI `server/dsh-table-store.ts`、`server/live-game-store.ts`、`server/replay-store.ts`。恢复验证必须覆盖实际游戏状态，不止恢复一个 `gameId` 或页面地址。

### 6.2 开始迁移前必须交付

1. 依赖与许可清单、源版本/资源哈希、可抽取范围及需用户决定的缺口。
2. 模块与构建发布方案、服务生命周期、存储选型、权限边界、旧局兼容和逐阶段回滚方案；具体字段、数据库和进程形态尚未锁定。
3. 固定回归用例与确认后的不变量：真实 `/hand/` 不变，原血战规则/计分不变，AI 与真人动作均校验，暗牌与问答授权隔离，同局切换不丢状态。

以上是实施前产物与未来验收要求，不是已完成的抽取清单或测试报告。本次只同步技术路线；商业模式讨论不自动变成收费功能、课程系统或云服务需求，也不改变独立可运行与官方插件的承诺。
